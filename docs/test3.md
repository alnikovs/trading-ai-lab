# test3 — подробное описание и инструкция по реализации

## Подробное описание

**Цель.** Сформировать полный сценарий, который подтверждает, что оркестратор корректно обслуживает цикл «ChatGPT → очередь команд → Cursor → сохранение результата» и отражает прогресс задачи в `memory/tasks.json`.

**Область покрытия.**
- сформировать входные данные: новое сообщение пользователя и существующая задача в `memory/tasks.json`;
- создать команду в `memory/commands.json`, отследить её статус и убедиться, что результат попадает в список `results`;
- проверить, что `/for-cursor/commands` выдаёт только команды со статусом `pending` и скрывает выполненные;
- зафиксировать результат через `/from-cursor/result` и убедиться, что история задач обновлена методом `/tasks/update`.

**Участники.**
- ChatGPT (инициирует задачу и формирует команду через `/from-chatgpt/command`);
- Cursor Cloud Agent (получает команду через `/for-cursor/commands`, исполняет и отправляет отчёт на `/from-cursor/result`);
- Task storage (`memory/tasks.json`) и commands storage (`memory/commands.json`).

**Результат.** После прохождения сценария в системе должны быть:
1. задача со статусом `in_progress` или `done`;
2. команда со статусом `ok` (или `error`, если тест моделирует неуспех) и привязанным результатом;
3. записанная история действий, доступная через `/for-chatgpt/results`.

## Инструкция по реализации

1. **Подготовить фикстуры.**
   - В `memory/tasks.json` добавить или убедиться, что существует задача с идентификатором `test3` (статус `open`, краткое описание цели теста).
   - Очистить или создать свежие файлы `memory/commands.json` и `memory/messages_test3.jsonl`, чтобы легко отслеживать изменения.

2. **Смоделировать запрос пользователя.**
   - Отправить POST-запрос на `/chat` c телом `{"user_id": "test3", "message": "Запусти сценарий test3"}`.
   - Убедиться, что ответ содержит `command_id`. Проверить, что новая запись появилась в `memory/commands.json` со статусом `pending`.

3. **Проверить очередь Cursor.**
   - Вызвать GET `/for-cursor/commands` и убедиться, что там присутствует ровно что созданная команда и нет выполненных.

4. **Эмулировать выполнение.**
   - Сформировать POST на `/from-cursor/result` со структурой:
     ```json
     {
       "command_id": "<ID из шага 2>",
       "status": "ok",
       "result": {
         "message": "test3 scenario executed",
         "artifacts": ["logs/test3.log"]
       }
     }
     ```
   - Проверить, что в `memory/commands.json` статус команды изменился, а в секции `results` добавлена запись.

5. **Закрыть задачу.**
   - Вызвать POST `/tasks/update` с телом `{"id": "test3", "status": "done"}`.
   - Убедиться, что `updated_at` обновлён, а `GET /tasks` показывает новый статус.

6. **Валидация.**
   - GET `/for-chatgpt/results?task_id=test3` должен возвращать хотя бы один результат с `status: ok`.
   - Просмотреть `memory/messages_test3.jsonl`, чтобы убедиться, что история запроса корректно сохранена.

## Критерии приёмки
- Полный цикл команды проходит без ошибок (все HTTP-ответы 200).
- После обновления задачи и результатов повторный вызов `/for-cursor/commands` не возвращает обработанную команду.
- При рестарте приложения и повторном вызове `/for-chatgpt/results` данные о выполнении test3 сохраняются.

## Дополнительные примечания
- Для интеграционных тестов можно использовать `pytest` + `httpx.AsyncClient`, подключив FastAPI-приложение как test client.
- Если требуется повторное выполнение сценария, перед стартом очистите файлы памяти или используйте уникальные `command_id`.
